# W1.3 R3 canonical read repair

## Root cause

GET had a local canonical ALS/AES validator, while workspace snapshots queried
runtime rows and used a divergent projection that omitted lifecycle-only rows
and did not bind `checkpointNamespace` to the assessment. The SSE controller
also converted snapshot failures to `EMPTY`, and the durable protocol test sat
under `tests/` while importing five `apps/api/src` modules across the approved
package boundary.

## Fix

`apps/api/src/platform/runtime-events/canonical-assessment-projection.ts` now
owns the persisted-row projection used by GET and workspace snapshots. It
enumerates `Assessment` rows with the nullable runtime relation, permits only
the genuine all-null V1 absence, rejects partial/malformed canonical pairs,
and requires `checkpointNamespace === assessmentId`; generated-client and
database errors propagate through the existing GET/global-filter and SSE
observable paths. The controller no longer masks snapshot errors as `EMPTY`;
it emits one terminal `error` SSE event using the shared problem envelope,
preserving a canonical `HttpException` problem and mapping unknown database
or generated-client failures to privacy-safe internal-error metadata.

The protocol test is now under `apps/api/test/` with package-local imports,
and `tests/assessment-lifecycle-migrated-db.mjs` runs
`test/assessment-lifecycle-protocol.test.ts`; no import-policy exception or
production legacy-path deletion was added.
