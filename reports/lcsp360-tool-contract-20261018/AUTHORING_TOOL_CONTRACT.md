# Rule Authoring tool contract

Generated by `build-tool-contract.py` from the live tool definitions; `test_authoring_tool_contract_document_matches_runtime` fails on drift.

## Rejection layers

- **Layer A - TOOL_SCHEMA**: The tool-argument contract refused the call; the mutation body never ran.
  - `TOOL_PREFLIGHT`: the tool wrapper's JSON-schema check (missing/mistyped/unknown/duplicate/out-of-enum arguments)
  - `FRAMEWORK_UNKNOWN_TOOL`: the model named a tool that does not exist; ToolNode answers, no LCSP code ran before this change
  - `FRAMEWORK_UNPARSEABLE_ARGUMENTS`: the model's tool-call arguments were not valid JSON; the call never executes and the model receives no tool answer
  - `FRAMEWORK_TOOL_ERROR`: any other ToolNode error message (status=error) not produced by the tool itself
- **Layer B - AUTHORING_PRECONDITION**: The body ran and refused a semantic precondition before touching the draft.
- **Layer C - REAL_RULE_VALIDATION**: The authored draft exists and the Compliance Rule Set validator executes. A different event family (RULE_VALIDATION_STARTED/PASSED/FAILED); never an authoring rejection.

## Persistence and restart

- **draft**: in-process run context (context.draft); not persisted API-side before submission
- **frozenInventory**: persisted API-side per revision (RuleSetPreparationClaimInventory); immutable
- **rejections**: published as durable stream events (RULE_AUTHORING_TOOL_REJECTED with a sanitized envelope; RULE_AUTHORING_REJECTION_RESOLVED when it ends) and kept in context.rejection_log (last 200)
- **checkpointing**: the Preparation graph is built with checkpointer=False and is claim-once: nothing resumes an in-flight run after a process restart. 'Restart' in tests means a rebuilt graph over live run state.

### `get_claim_inventory` (READ)

Read exact claims (statement, actor/action, provenance), relations, unaccounted claims or Requirements, one bounded page at a time. The reply states requestedLimit, appliedLimit, offset, returnedCount, hasMore and nextOffset; a page size above 20 is capped at 20 and reported, never rejected. | `claim_id` | `{"type": "string", "minLength": 1, "maxLength": 8000}` | no |
| `offset` | `{"type": "integer"}` | no |

### `author_legal_requirement` (MUTATION)

| `applicability_claim_ids` | `{"type": "array", "items": {"type": "string", "minLength": 1}, "maxItems": 128, "uniqueItems": true}` | yes |
| `qualifier_claim_ids` | `{"type": "array", "items": {"type": "string", "minLength": 1}, "maxItems": 128, "uniqueItems": true}` | no |
| `exception_claim_ids` | `{"type": "array", "items": {"type": "string", "minLength": 1}, "maxItems": 128, "uniqueItems": true}` | no |
| `context_claim_ids` | `{"type": "array", "items": {"type": "string", "minLength": 1}, "maxItems": 128, "uniqueItems": true}` | no |
| `non_repository_duty` | `{"type": "boolean"}` | no |
| `non_assessable_reason` | `{"type": "string", "minLength": 1, "maxLength": 8000}` | no |

- unknown arguments rejected: True
- idempotency: requirement_key; an identical resend leaves the draft fingerprint and revision unchanged, different content under the same key replaces the row (+1 draft revision)
- mutation: adds or replaces context.draft.legalRequirements[requirement_key]; re-derives contextRelations; invalidates any cached validation
- constraint: every claim ID must exist in the frozen inventory and be RELEVANT (INTENTIONALLY_NON_OPERATIVE claims cannot be bound)
- constraint: a claim's accounting role follows its claim type and must match the argument it is supplied in: operative_claim_ids=DUTY|PROHIBITION|PERMISSION; applicability_claim_ids=SCOPE|CONDITION only; qualifier_claim_ids=QUALIFIER|TEMPORAL_RULE|TRANSITION_RULE; exception_claim_ids=EXCEPTION; context_claim_ids=CONTEXT|CROSS_REFERENCE|DEFINITION
- constraint: operative_claim_ids must be non-empty (declared minItems 1; the body returns the richer OPERATIVE_PROPOSITION_REQUIRED with candidates)
- constraint: an assessable Requirement needs at least one applicability claim unless non_assessable_reason is given

- rejection TOOL_SCHEMA: `CLAIM_SCHEMA_INVALID` (MISSING_ARGUMENT, WRONG_TYPE, UNKNOWN_ARGUMENT, INVALID_ENUM, DUPLICATE_ITEMS, INVALID_VALUE)
