# Deterministic source review frontier

Root cause: the previous Agent had to reconcile an exact global set of claim IDs for every non-empty AST node. The required set included heading-only containers; claims added later silently invalidated prior in-memory reviews. The final repeated failure was on a body-bearing definitions node, so container filtering alone would not fix it. See FORENSICS.md and the retained 23 discovery-operation observations. Original final review payloads and twelve pending node IDs were not recorded and cannot be reconstructed.

Fix: derive a pinned review frontier, lease one bounded unit, let the Agent interpret it, validate a typed disposition and commit its claim payload transactionally. The runtime collects canonical claim IDs by unit, schedules the next unit, and computes completion eligibility. It never classifies raw legal prose.

Reviewable units contain source content. A parent whose own content is only its parser-recognized structural heading is ancestor context when children carry the body. Parent introductions beyond the heading and source-bearing leaves remain independent units. This preserves the AST and all chunk/node identities. The real failed 17-node fixture has 11 body units instead of 16 independent dispositions.

The frontier is keyed by Preparation and inventory revision, with source version/materialization foreign keys. Its definition fingerprint hashes sorted unit IDs and the pinned structural revision. States are PENDING, IN_REVIEW, REVIEWED_WITH_CLAIMS, REVIEWED_NO_CLAIMS, BLOCKED_REFERENCE and REOPENED. One row lock and one active-lease unique index serialize logical operations. Retrying the same operation or identical completion is idempotent. An expired lease can be reacquired.

The Agent calls get_next_review_unit. It receives one source text window, path, up to three ancestors, bounded references, effect status and existing claims when reopened. Additional windows and graph traversal remain available. Claim registration defaults to this source node and returns a stable canonical ID. IDs derive from Preparation, inventory revision, source anchors and a normalized stable semantic key; generated wording and call order do not define identity.

complete_source_review accepts CLAIMS_AUTHORED, CONTEXT_ONLY, NO_RELEVANT_SEMANTIC_CLAIMS or REQUIRES_REFERENCE_RESOLUTION. It normally collects all claims authored in the active unit. Explicit partial claim lists return exact missing IDs. Context-only cannot hide a normative claim. No-claim needs a reason and zero claims. Completing a parent never completes siblings or children.

Claims, relations, provenance anchors, explicit-reference accounting and disposition commit together. Completed review evidence survives process restart; the runtime restores it in internal pages without sending the global ledger to the model. Partial uncompleted claims remain draft work, and their unit stays unfinished. Correcting a completed unit requires explicit reopening with a recorded reason. Relations owned by another review cannot be silently removed.

References assigned to a heading-only container are routed to one body unit. Materiality and legal relation direction remain Agent-authored. Blocking yields the active lease so other queued targets can be reviewed. Completing all referenced target work requeues the waiting unit. Already-reviewed targets cannot create an unwakeable block. Outside-scope targets require explicit expansion with source edge and reason; expansion increments frontier revision. Existing target work is reused. Scoped frontiers are diagnostic-only; normal authoring includes every derived review unit.

Counters are maintained transactionally. The effective state fingerprint uses a commutative accumulator over current item fingerprints, independent of operation order, lease timestamps or cosmetic reason rewording. No-progress still emits feedback on unchanged state/gaps and terminates an ineffective repeat after feedback. It has no model-call budget.

Finalization requires zero pending/in-review/blocked units and valid source/claim/reference bindings. The API reconstructs the candidate from committed reviews, rejects divergence, freezes reviewedFrontierFingerprint and the existing immutable inventory revision/digest, then enters CLAIM_INVENTORY_READY. Rule authoring keeps the prior frozen-denominator protocol and downstream authority checks.

The additive 118th migration adds two review tables, indexes/constraints and diagnostic/fingerprint metadata. Historical inventories and Rule Sets keep their previous optional marker semantics; no fake review frontier is generated retroactively. New finalization requires the frontier. Database triggers prevent frozen review mutation and Rule Set insertion for discovery-only diagnostics.

The live harness uses the real Managed Deep Agent and six truthful synthetic source units on an explicitly isolated database. Its supported diagnostic lifecycle sets claimDiscoveryOnly, emits no Preparation dispatch/outbox event and stops at frozen inventory. Rule authoring/validation/submission tools are absent, API handlers reject them, and a database trigger prevents Rule Set persistence. It records safe graph progress and provider-reported usage without prompts or hidden reasoning. An exclusive launch journal prevents a second live invocation.

No production Preparation, source reindex, Rule Set authority change or Assessment repin is part of this task. A successful discovery-only run permits reporting FULL_SEMANTIC_DISPOSABLE=READY_FOR_SEPARATE_AUTHORIZATION; it does not authorize that run or a full corpus run.
