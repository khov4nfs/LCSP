> **Historical pre-freeze documentation.** This document records the earlier design or implementation. Current architecture authority is [the canonical Architecture Freeze](../../../reports/architecture-freeze-migration-manifest.md); current runtime names and release status must be read there and in the current PR #367 receipts.

- (direction by user) Use a mandatory whole-repository deterministic scan, including StructuralAugmentor for every in-scope file, before LLM orchestration.
- (decision by user) LLM agents receive sanitized metadata, evidence references, line ranges, and bounded graph slices; raw source, full prompts, secrets, and full AST bodies are forbidden.
- (decision by user) Use LangGraph as a checkpointed orchestrator with typed agent outcomes and deterministic policy gates; agents cannot freely call shell commands or persist authoritative decisions.
- (decision by user) A NEEDS_INPUT outcome carries typed missing requirements and allowed resolvers; the orchestrator uses a fixed resolver map, budget, retry, and fallback policy.
- (decision by user) Provide query, verification, similarity, flow-trace, artifact-chain, legal retrieval, classification, gap, and corpus-recovery tools as a versioned allow-listed registry.
- (decision by user) Admin-managed official legal-source catalog removes manual source approval; extraction and activation remain automated hash, hierarchy, chunk, index, and audit validation gates.
- (constraint by user) Legal matching and classification remain citation-backed and fail closed for unresolved conflict, unknown material fact, missing citation, invalid corpus/index, or insufficient scan coverage.
- (capability by user) CAP-1: The system exposes read-only technical evidence query and bounded static-analysis tools so agents can verify Wizard targets and discover analogous source patterns.
- (capability by user) CAP-2: The system routes typed missing-input outcomes to allowed tools or specialized agents and resumes from durable checkpoints without repeating completed work.
- (capability by user) CAP-3: The system produces only deterministic-validated, evidence-backed classification proposals and gap matrices from the immutable artifact chain and approved legal retrieval context.
- (capability by user) CAP-4: The system automatically recovers missing legal corpus context from admin-managed official sources through extraction/OCR fallback, chunk/index validation, and audited activation.
- (event by user) Express distillation selected because the user supplied the architecture, tool, authority, and automation decisions.
- (event) Coherence validation passed: five-field kernel contains stable CAP-1 through CAP-5, explicit constraints, non-goals, success signal, and open questions.
- (event) Preservation validation passed: mandatory full scan, sanitized LLM tools, typed orchestration, classification/gap gates, Admin-managed source automation, OCR fallback, chunk/index validation, and resume behavior are captured in the kernel or companions.
- (event) Updated legal-corpus-source authority to replace per-run manual source approval with Admin-managed official-source catalog and automatic activation after validation.
- (event) Aligned legal-corpus ingestion implementation guidance with Admin-managed source catalog and automated validation/activation terminology.
