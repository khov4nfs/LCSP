- (decision) Canonical implementation requirements live in docs/specs/functional-requirements.md; PRD FR-E headings are narrative aliases and must not drive stories or traceability.
- (decision) RBAC is the authorization source of truth; role labels are attributes/templates only, enforcement is deny-by-default, server-side, versioned, and auditable.
- (decision) Manager is the assessment owner and is sufficient to complete the active MVP without external collaborator assignment.
- (decision) Developer invitation, task workspace, scoped policy assignment, and membership revocation are retired from active MVP and require new change control to return.
- (decision) OAuth/OIDC authenticates LCSP identity only; GitHub App read-only repository authorization is a separate boundary and login grants no scan access.
- (decision) Risk classification is evidence-gated: technical evidence, schema and quality gates, reconciliation, legal provenance, and unresolved-conflict checks must pass before final output.
- (decision) Wizard-only assessments may provide readiness guidance but never HIGH/MEDIUM/LOW risk or equivalent final classification.
- (decision) Repository analysis uses a commit-pinned Deep Agents workspace; raw source must not go to LLM or long-term persistence, and direct source remains evidence authority.
- (decision) Real configured LLM providers are required for integrated acceptance, while deterministic mock gateways are limited to tests and offline development.
- (decision) Structured attestation and manual technical evidence JSON upload are removed/superseded; Local/CI report upload is not an active MVP evidence path.
- (decision) Material authorization, evidence, conflict, classification, retrieval, report, and document decisions require versioned, redacted audit trace with correlation.
- (decision) The existing PRD contains no canonical shared-wallet, pricing, per-invocation debit, settlement, reconciliation, or compensation authority, which is the approved Prompt 8 change signal.
- (decision) Prompt 8 becomes active MVP authority for one shared prepaid wallet per customer and per-physical-invocation model-usage settlement; paid-tool billing remains deferred.
- (decision) Authorization is RBAC-only and owner/resource-scoped with assessment.ownerId and wallet.userId; organization and active Developer collaboration are retired.
- (decision) Canonical Prompt 8 requirements use FR-083..FR-094 and NFR-036..NFR-042 because FR-057..FR-082 remain historical aliases.
- (decision) One VND of confirmed pre-tax service value equals one public credit, and one public credit equals 1,000,000 internal microcredits; customer transaction tax never becomes spendable credit.
- (decision) Initial Pricing Draft assumptions are FX 26,500 VND/USD, infrastructure overhead 10 percent of converted provider cost, and markup multiplier 1.8 on estimated loaded cost; these are editable versioned assumptions, not runtime constants.
- (decision) Runtime settlement uses immutable published microcredit-per-token tariffs and never recalculates provider FX, markup, or customer transaction tax per invocation.
- (decision) No arbitrary lower business token/output cap is introduced before an approved telemetry policy; wallet admission and existing runtime/no-progress controls remain independent.
- (decision) Production debit remains disabled until all seven approved enablement gates have GREEN, rollback, and operational evidence.
- (change) Update PRD and canonical FR/NFR catalogs to add shared wallet, pricing, admission, settlement, payment-required, reconciliation, compensation, telemetry, migration, and enablement requirements.
- (change) Reconciled the canonical use-case, business-rule, acceptance-criteria and traceability summaries with Prompt 8 authority and retired organization semantics.
- (decision) PRD status is final for downstream architecture, UX, epic/story and RED-test work, while readiness remains conditional for production model-usage debit and customer tariff approval.
- (decision) Prompt 8 financial enablement is tracked as validation dependency A4; the editable Pricing Draft assumptions cannot satisfy the seven production gates by themselves.
- (change) Rubric and input reconciliation added Customer/Admin protagonists and journeys, a canonical glossary, technical-only verification consistency, measurable gate IDs G-01..G-07, loaded-cost components, shadow delivery sequence and Prompt 8 UX authority.
- (decision) Product requirements retain atomic/idempotent financial outcomes and reversible exact-value migration as invariants; transaction write sets, shadow-column topology and cutover mechanics move to ADR-028.
- (decision) Final PRD status means final product direction, not unconditional implementation acceptance; Wizard critical-unknown, legal-corpus acceptance, source-retention/evidence-quality policy and production debit remain named conditional capabilities with explicit acceptance gates.
- (change) RBAC wording now recognizes Customer wallet/payment and permissioned Billing/Pricing Admin actors while preserving Manager as the only customer-facing assessment decision role.
